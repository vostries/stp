## 1. Цель работы

Получить практические навыки настройки CI-конвейера с использованием GitHub Actions. Научиться:

- запускать сборку и автоматические тесты на разных операционных системах;
- использовать матрицу заданий (`strategy.matrix`);
- управлять зависимостями между заданиями;
- кэшировать результаты сборки и зависимости;
- сохранять артефакты CI.

## 3. Задание

### Часть 1. Подготовка репозитория

**Задачи:**

1. Создать собственный репозиторий GitHub на основе предоставленного проекта.
2. Проверить возможность локальной сборки проекта и прохождения тестов.
3. Изучить структуру проекта, используемые зависимости и команды сборки и тестирования.
4. Подготовить репозиторий к автоматическому запуску CI при изменении исходного кода.

### Часть 2. Создание CI-конвейера

**Триггеры:**

- события `push` и `pull_request`.

**Конвейер должен выполнять:**

1. Получить исходный код репозитория.
2. Настроить среду сборки.
3. Установить необходимые зависимости.
4. Сконфигурировать проект с помощью CMake.
5. Собрать приложение.
6. Запустить автоматические тесты.
7. Завершить выполнение с ошибкой, если сборка или тестирование не прошли.

### Часть 3. Сборка на разных операционных системах

**Матрица ОС:**

- `ubuntu-latest`
- `macos-latest`
- `windows-latest`

**Единые требования:**

- стандарт языка C++17, одинаковый исходный код и одинаковый набор тестов во всех конфигурациях.

**Задачи:**

1. Использовать `strategy.matrix` для описания операционных систем.
2. Выполнять сборку и тестирование на каждой операционной системе.
3. Обеспечить корректную установку зависимостей и настройку CMake для каждой платформы.
4. Проверить результаты всех трёх заданий.
5. Объяснить, почему успешная сборка на одной ОС не гарантирует успешную сборку на остальных.

### Часть 4. Параметр fail-fast

**Задачи:**

1. Настроить `fail-fast: false` в матрице.
2. Временно внести контролируемую ошибку в один из тестов.
3. Запустить workflow и зафиксировать, как завершаются задания на разных ОС.
4. Изменить значение параметра на `fail-fast: true` и повторить эксперимент.
5. Сравнить результаты и объяснить влияние `fail-fast` на выполнение матрицы.

**После:**

- восстановить тесты и убедиться, что все задания снова проходят успешно.

### Часть 5. Кэширование

**Задачи:**

1. Выбрать подходящие данные для кэширования: например, загруженные зависимости или результаты компиляции.
2. Настроить ключ кэша с учётом операционной системы и файлов, от которых зависит содержимое кэша.
3. Выполнить первый запуск workflow и зафиксировать время.
4. Повторить запуск без изменения проекта и зафиксировать время.
5. Изменить один исходный файл и повторить запуск.
6. Сравнить результаты и объяснить, когда кэширование приносит пользу и почему оно не гарантирует ускорение каждого запуска.

### Часть 6. Артефакты

**Цель:**

- настроить сохранение результатов CI в виде артефактов GitHub Actions.

**Минимум:**

- сохранить отчёт о тестировании или журнал результатов тестов. Дополнительно можно сохранить собранное приложение.

**Задачи:**

1. Настроить загрузку артефактов после выполнения тестов.
2. Убедиться, что артефакты доступны в интерфейсе GitHub Actions.
3. Скачать один из артефактов и проверить его содержимое.
4. Объяснить разницу между кэшированием и артефактами.
